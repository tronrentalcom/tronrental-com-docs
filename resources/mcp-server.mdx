## What is MCP?

[Model Context Protocol (MCP)](https://modelcontextprotocol.io) is an open standard that lets AI agents (Claude Code, Cursor, Windsurf, and others) interact with external services through a unified interface.

TronRental provides an official MCP server that gives AI agents full access to the energy purchasing API — from checking prices to completing purchases.

## Quick Start

Add to your AI agent:

```bash
npx -y @tronrental-com/mcp-server
```

### Claude Code

```bash
# Without API key (the agent registers an account with your email)
claude mcp add tronrental -- npx -y @tronrental-com/mcp-server

# With API key
claude mcp add tronrental -e TRONRENTAL_API_KEY=your_key -- npx -y @tronrental-com/mcp-server
```

### Cursor / Windsurf

Add to your MCP configuration:

```json
{
  "mcpServers": {
    "tronrental": {
      "command": "npx",
      "args": ["-y", "@tronrental-com/mcp-server"],
      "env": {
        "TRONRENTAL_API_KEY": "your_key"  // pragma: allowlist secret
      }
    }
  }
}
```

The `TRONRENTAL_API_KEY` environment variable is optional. If not provided, the agent can register a new account and create an API key through the MCP tools. The agent asks for your email: TronRental mails a 6-digit code there, and the account is created only after you give that code to the agent.

## Available Tools

The MCP server provides 12 tools:

| Tool | Auth | Description |
|------|------|-------------|
| `get_prices` | None | Current energy and bandwidth prices |
| `calculate_savings` | None | Calculate savings: burn cost vs rental cost |
| `register` | None | Start registration: mails a 6-digit code to the user's email |
| `verify_email_code` | None | Confirm the code and create the account |
| `resend_email_code` | None | Mail a new code (expired or not received) |
| `login` | None | Log in to existing account |
| `create_api_key` | Token | Create an API key |
| `get_deposit_address` | API key | Get TRX deposit address |
| `get_balance` | API key | Check account balance |
| `buy_energy` | API key | Buy energy for a TRON address |
| `get_order` | API key | Check order status |
| `regenerate_deposit_address` | API key | Generate a new deposit address |

## Typical Flow

### New user (no API key)

1. `get_prices` — show current pricing
2. `calculate_savings` — calculate savings for user's transfer volume
3. `register` — the user's real email and a password; a 6-digit code is mailed there
4. The user reads the code from the email and gives it to the agent
5. `verify_email_code` — creates the account and signs in
6. `create_api_key` — generate API key
7. `get_deposit_address` — get deposit address, user sends TRX
8. `get_balance` — verify deposit arrived
9. `buy_energy` — purchase energy
10. `get_order` — confirm delegation

<Note>
  The agent never invents an email address: without a code from a real inbox no account is created. The code is valid for 10 minutes; `resend_email_code` sends a new one (up to 3 emails per hour). The same steps over plain HTTP are described in [Authentication](/authentication#signing-up-via-the-api-ai-agents).
</Note>

### Existing user (API key set)

1. `get_balance` — check balance
2. `buy_energy` — purchase energy
3. `get_order` — confirm delegation

## Energy Amounts

| Scenario | Energy |
|----------|--------|
| Recipient already has USDT | 65,000 |
| Recipient never held USDT | 131,000 |
| Minimum order | 1 |
| Maximum order | 5,000,000 |

Duration is always `1h` — energy is used within seconds, 1 hour is the rental window.
