## त्रुटि प्रारूप

त्रुटियां तीन में से किसी एक रूप में आती हैं। अधिकांश एंडपॉइंट पहला रूप उपयोग करते हैं; अन्य दो विशिष्ट
पथों पर मिलते हैं और यहां इसलिए सूचीबद्ध हैं ताकि आपका क्लाइंट वह त्रुटि कोड न चूके जिसे वह खोज रहा है।

**मानक।** प्रोग्रामेटिक हैंडलिंग के लिए `code`, जो `detail.error` के भीतर होता है:

```json
{
  "detail": {
    "error": {
      "code": "INSUFFICIENT_BALANCE",
      "message": "Insufficient balance. Required: 12.5 TRX, available: 3.1 TRX"
    }
  }
}
```

**खाता-स्तरीय रेट लिमिट।** वही फ़ील्ड, पर शीर्ष स्तर पर और `detail` के बिना — यह प्रतिक्रिया अनुरोध के
एंडपॉइंट तक पहुंचने से पहले ही बन जाती है:

```json
{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests. Please try again later."}}
```

**सपाट।** निकासी सत्यापन के चरण `code` को `detail` के बगल में रखते हैं, और `detail` में स्वयं संदेश होता है:

```json
{"detail":"Passkey verification required","code":"PASSKEY_REQUIRED"}
```

कुछ प्रतिक्रियाओं में कोई कोड होता ही नहीं — अनुरोध सत्यापन (`422`) और कुछ आंतरिक जांचें सादे संदेश के साथ
`{"detail": "..."}` लौटाती हैं।

<Tip>
कोड इनमें से पहले उपलब्ध फ़ील्ड से पढ़ें: `detail.error.code`, फिर `error.code`, फिर `code`। इनमें से कोई
न हो तो HTTP स्थिति पर भरोसा करें, और कभी यह न मानें कि `detail` एक स्ट्रिंग है — मानक रूप में यह एक ऑब्जेक्ट
होता है।
</Tip>

## HTTP स्थिति कोड

| कोड | अर्थ |
|------|---------|
| `200` | सफल |
| `400` | गलत अनुरोध — अमान्य पैरामीटर |
| `401` | अनधिकृत — API कुंजी गायब या अमान्य |
| `402` | भुगतान आवश्यक — खाते की शेष राशि बहुत कम |
| `403` | निषिद्ध — कुंजी अक्षम, IP श्वेतसूची में नहीं, या सत्यापन आवश्यक |
| `404` | नहीं मिला |
| `409` | संघर्ष — दोहराया गया अनुरोध या संसाधन संघर्ष |
| `422` | सत्यापन त्रुटि — अनुरोध बॉडी जांचें |
| `429` | रेट लिमिट पार — देखें [रेट लिमिट](/resources/rate-limits) |
| `500` | सर्वर त्रुटि |
| `503` | अस्थायी रूप से अनुपलब्ध — कुछ देर बाद पुनः प्रयास करें |

## सामान्य त्रुटि कोड

मानक रूप में, `detail.error.code` के अंतर्गत लौटाए जाते हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `INVALID_TOKEN` | `401` | API कुंजी गायब, अज्ञात या अक्षम |
| `ACCOUNT_BLOCKED` | `403` | इस खाते के लिए API पहुंच अवरुद्ध है |
| `FORBIDDEN` | `403` | अनुरोध का IP कुंजी की श्वेतसूची में नहीं है |
| `INSUFFICIENT_BALANCE` | `402` | इस कार्रवाई के लिए खाते की शेष राशि पर्याप्त नहीं |
| `INVALID_ADDRESS` | `400` | मान्य TRON पता नहीं है |
| `CONTRACT_ADDRESS_NOT_SUPPORTED` | `400` | लक्ष्य एक स्मार्ट कॉन्ट्रैक्ट है — TRON उस पर संसाधन प्रत्यायोजित करने की अनुमति नहीं देता |
| `INVALID_VOLUME` | `400` | अनुरोधित मात्रा अनुमत सीमा से बाहर है |
| `INVALID_DURATION` | `400` | अवधि स्वीकृत मानों में से नहीं है |
| `ORDER_NOT_FOUND` | `404` | ऑर्डर ID मौजूद नहीं है |
| `RATE_LIMIT_EXCEEDED` | `429` | बहुत अधिक अनुरोध — देखें [रेट लिमिट](/resources/rate-limits) |

## निकासी सत्यापन कोड

`POST /api/v1/account/withdrawal` इन्हें सपाट रूप में लौटाता है, जहां `code` और `detail` साथ-साथ होते हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `WITHDRAW_SCOPE_REQUIRED` | `403` | API कुंजी में `withdraw` स्कोप नहीं है |
| `2FA_REQUIRED` | `403` | 2FA सक्षम करना होगा, या कोड देना होगा |
| `IP_WHITELIST_REQUIRED` | `403` | निकासी से पहले कुंजी को IP श्वेतसूची चाहिए |
| `PASSKEY_REQUIRED` | `403` | खाते में पासकी है — निकासी के लिए वह आवश्यक है |
| `INVALID_PASSKEY` | `403` | पासकी चैलेंज अमान्य, समाप्त, या आपका नहीं |
| `INVALID_2FA_CODE` | `403` | 2FA या बैकअप कोड अस्वीकृत |
| `RATE_UNAVAILABLE` | `503` | विनिमय दर अस्थायी रूप से अनुपलब्ध — कुछ देर बाद प्रयास करें |

## पुनः प्रयास रणनीति

`5xx` प्रतिक्रियाओं के लिए घातीय बैकऑफ़ के साथ पुनः प्रयास करें। `429` के लिए, यदि प्रतिक्रिया में
`Retry-After` हेडर हो तो उसे प्राथमिकता दें, और पहले बॉडी पढ़ें — हर `429` रेट लिमिट नहीं होता
(देखें [रेट लिमिट](/resources/rate-limits))।

```python
import time
import requests

def api_call_with_retry(url, **kwargs):
    for attempt in range(3):
        resp = requests.get(url, **kwargs)
        if resp.status_code == 429:
            time.sleep(int(resp.headers.get("Retry-After", 2 ** attempt)))
            continue
        if resp.status_code >= 500:
            time.sleep(2 ** attempt)
            continue
        return resp
    raise Exception("Max retries exceeded")
```
