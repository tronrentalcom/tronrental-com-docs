## त्रुटि प्रारूप

त्रुटियां तीन में से किसी एक रूप में आती हैं। अधिकांश एंडपॉइंट पहला रूप उपयोग करते हैं; अन्य दो विशिष्ट
पथों पर मिलते हैं और यहां इसलिए सूचीबद्ध हैं ताकि आपका क्लाइंट वह त्रुटि कोड न चूके जिसे वह खोज रहा है।

**मानक।** प्रोग्रामेटिक हैंडलिंग के लिए `code`, जो `detail.error` के भीतर होता है:

```json
{
  "detail": {
    "error": {
      "code": "INSUFFICIENT_BALANCE",
      "message": "Insufficient balance. Required: 12.5 TRX, available: 3.1 TRX"
    }
  }
}
```

**खाता-स्तरीय रेट लिमिट।** वही फ़ील्ड, पर शीर्ष स्तर पर और `detail` के बिना — यह प्रतिक्रिया अनुरोध के
एंडपॉइंट तक पहुंचने से पहले ही बन जाती है:

```json
{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests. Please try again later."}}
```

**सपाट।** निकासी सत्यापन के चरण `code` को `detail` के बगल में रखते हैं, और `detail` में स्वयं संदेश होता है:

```json
{"detail":"Passkey verification required","code":"PASSKEY_REQUIRED"}
```

हर प्रतिक्रिया में कोड नहीं होता। अनुरोध सत्यापन की विफलताएं फ्रेमवर्क के अपने प्रारूप में आती हैं, जहां
`detail` स्ट्रिंग नहीं, बल्कि फ़ील्ड-त्रुटियों का **ऐरे** होता है; कुछ आंतरिक जांचें सादे संदेश के साथ
`{"detail": "..."}` लौटाती हैं। वहीं कुछ `422` प्रतिक्रियाओं में कोड होता भी है, मानक रूप में — जैसे दोबारा
इस्तेमाल की गई आइडेम्पोटेंसी कुंजी।

<Tip>
कोड इनमें से पहले उपलब्ध फ़ील्ड से पढ़ें: `detail.error.code`, फिर `error.code`, फिर `code`। इनमें से कोई
न हो तो HTTP स्थिति पर भरोसा करें, और कभी यह न मानें कि `detail` एक स्ट्रिंग है: मानक रूप में यह ऑब्जेक्ट है
और सत्यापन त्रुटि में ऐरे।
</Tip>

## HTTP स्थिति कोड

| कोड | अर्थ |
|------|---------|
| `200` | सफल |
| `400` | गलत अनुरोध — अमान्य पैरामीटर |
| `401` | अनधिकृत — API कुंजी गायब या अमान्य |
| `402` | भुगतान आवश्यक — खाते की शेष राशि बहुत कम |
| `403` | निषिद्ध — कुंजी के पास आवश्यक स्कोप नहीं, IP श्वेतसूची में नहीं, सत्यापन आवश्यक, या नई API कुंजी के लिए खाते में पर्याप्त टॉप-अप नहीं |
| `404` | नहीं मिला |
| `409` | संघर्ष — दोहराया गया अनुरोध या संसाधन संघर्ष |
| `422` | सत्यापन त्रुटि — अनुरोध बॉडी जांचें |
| `429` | रेट लिमिट पार — देखें [रेट लिमिट](/hi/resources/rate-limits) |
| `500` | सर्वर त्रुटि |
| `503` | अस्थायी रूप से अनुपलब्ध — कुछ देर बाद पुनः प्रयास करें |

## सामान्य त्रुटि कोड

मानक रूप में, `detail.error.code` के अंतर्गत लौटाए जाते हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `INVALID_TOKEN` | `401` | API कुंजी गायब, अज्ञात या अक्षम |
| `ACCOUNT_BLOCKED` | `403` | इस खाते के लिए API पहुंच अवरुद्ध है |
| `FORBIDDEN` | `403` | कुंजी के पास इस एंडपॉइंट के लिए आवश्यक स्कोप नहीं है, या अनुरोध का IP कुंजी की श्वेतसूची में नहीं है |
| `NODE_API_KEY_ONLY` | `403` | इस API को Node API कुंजी भेजी गई — वह केवल `node.tronrental.com` पर काम करती है |
| `API_KEY_DEPOSIT_REQUIRED` | `403` | नई API कुंजी के लिए कुल 100 TRX के टॉप-अप चाहिए। कुंजी बनाते समय और इसी कारण बंद की गई कुंजी चालू करते समय लौटता है। `error.required_trx` सीमा है, `error.missing_trx` बाकी टॉप-अप राशि (TRX, स्ट्रिंग के रूप में) — देखें [प्रमाणीकरण](/hi/authentication) |
| `INSUFFICIENT_BALANCE` | `402` | इस कार्रवाई के लिए खाते की शेष राशि पर्याप्त नहीं |
| `PRICE_CHANGED` | `409` | ऑर्डर की लागत आपके भेजे गए `max_price_trx` से अधिक है। कुछ भी चार्ज नहीं हुआ — नया मूल्य अनुमान लें और पुनः प्रयास करें |
| `IDEMPOTENCY_KEY_REUSED` | `422` | यह Idempotency-Key पहले ही किसी दूसरी अनुरोध बॉडी के साथ इस्तेमाल हो चुकी है |
| `IDEMPOTENCY_KEY_TOO_LONG` | `422` | Idempotency-Key 64 अक्षरों से लंबी है |
| `IDEMPOTENT_REQUEST_IN_PROGRESS` | `409` | इस Idempotency-Key वाला अनुरोध अभी प्रोसेस हो रहा है। कुछ सेकंड रुकें और उसी कुंजी के साथ पुनः प्रयास करें — नई कुंजी पर न जाएँ |
| `IDEMPOTENCY_UNAVAILABLE` | `503` | Idempotency-Key जाँची नहीं जा सकी, इसलिए कुछ भी नहीं खरीदा गया। उसी कुंजी के साथ पुनः प्रयास करें |
| `INVALID_ADDRESS` | `400` | मान्य TRON पता नहीं है |
| `CONTRACT_ADDRESS_NOT_SUPPORTED` | `400` | लक्ष्य एक स्मार्ट कॉन्ट्रैक्ट है — TRON उस पर संसाधन प्रत्यायोजित करने की अनुमति नहीं देता |
| `INVALID_VOLUME` | `400` | अनुरोधित मात्रा अनुमत सीमा से बाहर है |
| `POOL_EXHAUSTED` | `503` | इस एड्रेस के लिए 32,000 से कम के एनर्जी ऑर्डर अस्थायी रूप से उपलब्ध नहीं हैं। कुछ भी चार्ज नहीं हुआ — बाद में पुनः प्रयास करें या 32,000 या अधिक ऑर्डर करें |
| `INVALID_DURATION` | `400` | अवधि स्वीकृत मानों में से नहीं है |
| `ORDER_NOT_FOUND` | `404` | ऑर्डर ID मौजूद नहीं है |
| `ORDER_NOT_RECLAIMABLE` | `409` | ऑर्डर अभी डिलीवर (`filled`) बैंडविड्थ ऑर्डर नहीं है या विफल हो गया — केवल ऐसा ऑर्डर वापस लिया जा सकता है |
| `RATE_LIMIT_EXCEEDED` | `429` | बहुत अधिक अनुरोध — देखें [रेट लिमिट](/hi/resources/rate-limits) |

<Note>
Node API (`node.tronrental.com`) के अपने त्रुटि कोड हैं, एक अलग प्रारूप में — देखें
[Node API → सीमाएँ और त्रुटियाँ](/hi/node-api/errors)।
</Note>

<Warning>
`INSUFFICIENT_BALANCE` हर जगह इस्तेमाल नहीं होता। `POST /api/v1/smart-mode/activate` और
`POST /api/v1/transfer-packages/buy` उसी स्थिति को `400` के रूप में बताते हैं — संदेश के साथ, पर **बिना
कोड** के: `{"detail":{"error":{"message":"Insufficient balance"}}}`। इन दो एंडपॉइंट पर केवल कोड देखकर
शेष राशि की समस्या न पहचानें।
</Warning>

## ऑटो रिफिल कोड

[ऑटो रिफिल](/hi/api-reference/auto-refill/overview) एंडपॉइंट इन्हें मानक रूप में लौटाते हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `AUTOREFILL_ADDRESS_TAKEN` | `409` | खाते में इस पते और संसाधन के लिए पहले से एक नियम है — उसी नियम को बदलें |
| `AUTOREFILL_IN_PROGRESS` | `409` | इस नियम के लिए अभी रिफिल खरीदा जा रहा है — बदलाव या हटाने का अनुरोध एक मिनट में दोबारा भेजें |
| `AUTOREFILL_DISABLED` | `503` | इस संसाधन के लिए ऑटो रिफिल अस्थायी रूप से बंद है; यह कोड केवल नियम बनाते समय लौटता है। कोई नियम नहीं बना — कुछ देर बाद पुनः प्रयास करें |
| `NOT_FOUND` | `404` | खाते में ऐसा कोई नियम नहीं है |

| `AUTO_BW_DISABLED` | `503` | ऑटो बैंडविड्थ अस्थायी रूप से बंद है; सब्सक्रिप्शन बनाते या फिर शुरू करते समय और कॉन्ट्रैक्ट जोड़ते समय लौटता है। कुछ नहीं बदला — कुछ देर बाद पुनः प्रयास करें |

## Transfer Package कोड

[Transfer Packages](/hi/api-reference/transfer-packages/overview) एंडपॉइंट इन्हें मानक रूप में लौटाते हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `ADDRESS_PAUSED` | `400` | पैकेज खरीदते समय: इस एड्रेस पर आपके पैकेज रुके हुए हैं — पहले उन्हें फिर से शुरू करें |
| `PACKAGE_NOT_FOUND` | `404` | रोकते, फिर से शुरू करते या ले जाते समय: एड्रेस पर खाते का आवश्यक स्थिति वाला कोई पैकेज नहीं है। वॉलेट को नाम देते, संग्रह में भेजते या वापस लाते समय: एड्रेस पर खाते का कोई पैकेज नहीं है |
| `PACKAGE_NOT_SETTLED` | `400` | रोकते, फिर से शुरू करते या ले जाते समय: एड्रेस पर कोई पैकेज अभी सक्रिय हो रहा है — बाद में पुनः प्रयास करें |
| `ADDRESS_SHARED` | `400` | रोकते या ले जाते समय: एड्रेस पर किसी दूसरे खाते का सक्रिय पैकेज है |
| `SMART_MODE_ACTIVE` | `400` | रोकते, फिर से शुरू करते या ले जाते समय: एड्रेस पर Smart Mode सक्रिय है (ले जाने पर — पुराने या नए एड्रेस पर) — पहले उसे बंद करें |
| `ADDRESS_BUSY` | `409` | एड्रेस पर कोई दूसरा ऑपरेशन चल रहा है — एक मिनट बाद पुनः प्रयास करें |
| `PAUSE_BUSY` | `429` | एक साथ बहुत सारे पैकेज रोके जा रहे हैं — एक मिनट बाद पुनः प्रयास करें। यह रेट लिमिट नहीं है |
| `PROVIDER_UNAVAILABLE` | `503` | रोकते, फिर से शुरू करते या ले जाते समय: एड्रेस पर एनर्जी की डिलीवरी बदली नहीं जा सकी। कुछ नहीं बदला — एक मिनट बाद पुनः प्रयास करें |
| `SAME_ADDRESS` | `400` | ले जाते समय: नया एड्रेस वही है जिस पर पैकेज हैं |
| `ADDRESS_NOT_ALLOWED` | `400` | ले जाते समय: पैकेज इस एड्रेस पर नहीं ले जाए जा सकते |
| `ADDRESS_TAKEN` | `409` | ले जाते समय: नए एड्रेस पर पहले से ट्रांसफर पैकेज हैं। यदि संदेश कहता है कि पैकेज पुराने एड्रेस पर रुके रहेंगे, तो स्थानांतरण रोकने के बाद थम गया — उन्हें वहीं फिर से शुरू करें या दोबारा ले जाएँ |
| `MOVE_AFTER_PAUSE` | `409` | ले जाते समय: कुछ पैकेज रोके जाने के 15 मिनट बाद ही ले जाए जा सकते हैं — उन्हें रोकें, 15 मिनट रुकें, फिर ले जाएँ |
| `MOVED_PAUSED` | कारण की स्थिति | ले जाते समय: पैकेज नए एड्रेस पर हैं पर वहाँ रुके रहते हैं — उन्हें नए एड्रेस के साथ फिर से शुरू करें |

## निकासी सत्यापन कोड

`POST /api/v1/account/withdrawal` इन सत्यापन कोड को सपाट रूप में लौटाता है, जहां `code` और `detail`
साथ-साथ होते हैं; उसी एंडपॉइंट की बाकी त्रुटियां मानक रूप में आती हैं:

| कोड | स्थिति | विवरण |
|------|--------|-------------|
| `WITHDRAW_SCOPE_REQUIRED` | `403` | API कुंजी में `withdraw` स्कोप नहीं है |
| `2FA_REQUIRED` | `403` | 2FA सक्षम करना होगा, या कोड देना होगा |
| `IP_WHITELIST_REQUIRED` | `403` | निकासी से पहले कुंजी को IP श्वेतसूची चाहिए |
| `PASSKEY_REQUIRED` | `403` | खाते में पासकी है — निकासी के लिए वह आवश्यक है |
| `INVALID_PASSKEY` | `403` | पासकी चैलेंज अमान्य, समाप्त, या आपका नहीं |
| `INVALID_2FA_CODE` | `403` | 2FA या बैकअप कोड अस्वीकृत |
| `RATE_UNAVAILABLE` | `503` | विनिमय दर अस्थायी रूप से अनुपलब्ध — कुछ देर बाद प्रयास करें |

## पुनः प्रयास रणनीति

`5xx` प्रतिक्रियाओं के लिए घातीय बैकऑफ़ के साथ पुनः प्रयास करें। `429` के लिए, यदि प्रतिक्रिया में
`Retry-After` हेडर हो तो उसे प्राथमिकता दें, और पहले बॉडी पढ़ें — हर `429` रेट लिमिट नहीं होता
(देखें [रेट लिमिट](/hi/resources/rate-limits))।

```python
import time
import requests

def api_call_with_retry(url, **kwargs):
    for attempt in range(3):
        resp = requests.get(url, **kwargs)
        if resp.status_code == 429:
            time.sleep(int(resp.headers.get("Retry-After", 2 ** attempt)))
            continue
        if resp.status_code >= 500:
            time.sleep(2 ** attempt)
            continue
        return resp
    raise Exception("Max retries exceeded")
```
