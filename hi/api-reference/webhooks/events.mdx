## वेबहुक लॉग

हाल के डिलीवरी प्रयास, नए सबसे ऊपर — हमने क्या भेजा और आपके सर्वर ने क्या उत्तर दिया।

### क्वेरी पैरामीटर

<ParamField query="page" type="integer">
  पेज संख्या, `1` से। डिफ़ॉल्ट `1`।
</ParamField>

<ParamField query="page_size" type="integer">
  प्रति पेज प्रविष्टियाँ, `1`–`100`। डिफ़ॉल्ट `50`।
</ParamField>

### प्रतिक्रिया

प्रविष्टियों की सूची।

<ResponseField name="id" type="number">
  लॉग प्रविष्टि ID।
</ResponseField>

<ResponseField name="event_type" type="string">
  कौन-सी घटना भेजी गई, जैसे `order.updated`।
</ResponseField>

<ResponseField name="payload" type="object">
  ठीक वही लिफ़ाफ़ा जो भेजा गया — `event` / `data` / `timestamp`, वही बाइट्स जिन पर हस्ताक्षर गिना गया।
</ResponseField>

<ResponseField name="response_status" type="number">
  आपके सर्वर ने जो HTTP स्थिति लौटाई। **`0` का अर्थ है कि कोई HTTP उत्तर आया ही नहीं** — कनेक्शन, TLS हैंडशेक या रीड विफल हुआ या टाइमआउट हो गया।
</ResponseField>

<ResponseField name="attempts" type="number">
  तीन में से कितने प्रयास किए गए। `1` यानी पहली ही बार सफल।
</ResponseField>

<ResponseField name="created_at" type="string">
  डिलीवरी कब पूरी हुई, ISO-8601।
</ResponseField>

### उदाहरण

```bash
curl https://api.tronrental.com/v1/webhooks/logs \
  -H "X-API-Key: your_api_key"
```

<Note>
  इस लॉग से डिबग करने से पहले दो बातें जान लें:

  - इसमें वे डिलीवरी दिखती हैं जो आपकी **API कुंजियों** से जुड़ी हैं, इसलिए `subscription.transfer` की डिलीवरी आज यहाँ नहीं दिखती, चाहे वे भेजी जा चुकी हों।
  - जो URL रिज़ॉल्व न हो सका, या जो निजी पते पर रिज़ॉल्व होता है, उससे **कोई पंक्ति बनती ही नहीं** — खाली लॉग «कोई घटना नहीं हुई» और «पता अस्वीकार हुआ» में अंतर नहीं करता। यदि ट्रैफ़िक अपेक्षित था और कुछ नहीं दिखता, तो [Dashboard → API](https://tronrental.com/dashboard/api) में URL जाँचें।
</Note>
