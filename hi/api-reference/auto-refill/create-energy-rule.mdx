## एनर्जी नियम बनाएं

एक एड्रेस के लिए ऑटो रिफिल नियम बनाता है। अगली जाँच से, जब भी एड्रेस पर उपलब्ध एनर्जी `threshold_energy` से कम होती है, हम एक घंटे के लिए `add_volume` एनर्जी खरीदते हैं और आपके बैलेंस से शुल्क लेते हैं। जाँच, लागत और स्थितियाँ कैसे काम करती हैं, यह जानने के लिए [अवलोकन](/api-reference/auto-refill/overview) देखें।

अनुरोध केवल नियम बनाता है — यह स्वयं कुछ नहीं खरीदता। `buy_energy` स्कोप आवश्यक है। पहले एक रिफिल की कीमत देखने के लिए [एनर्जी रिफिल मूल्य अनुमान](/api-reference/auto-refill/quote-energy-refill) का उपयोग करें।

### अनुरोध बॉडी

<ParamField body="target_address" type="string" required>
  वह TRON एड्रेस जिस पर आपूर्ति बनाए रखनी है (T... प्रारूप, 34 अक्षर)। कॉन्ट्रैक्ट एड्रेस अस्वीकार किए जाते हैं।
</ParamField>

<ParamField body="threshold_energy" type="number" required>
  जब एड्रेस पर उपलब्ध एनर्जी इससे कम हो, तब खरीदें। 1 से 50,000,000 तक।
</ParamField>

<ParamField body="add_volume" type="number" required>
  प्रति रिफिल खरीदी जाने वाली एनर्जी। 32,000 से 5,000,000 तक। इसे `threshold_energy` के बराबर या उससे ऊपर रखें — देखें [अवलोकन में चेतावनी](/api-reference/auto-refill/overview#choosing-the-numbers)।
</ParamField>

<ParamField body="duration" type="string" default="1h">
  हर रिफिल के किराये की अवधि। केवल `"1h"` स्वीकार किया जाता है; कोई अन्य मान `422` लौटाता है।
</ParamField>

<ParamField body="label" type="string">
  नियम के लिए आपका अपना नाम, अधिकतम 100 अक्षर। वैकल्पिक।
</ParamField>

### रिस्पॉन्स

नया नियम — वही फ़ील्ड जो [एनर्जी नियमों की सूची](/api-reference/auto-refill/list-energy-rules) में हैं — और साथ में इस समय के एड्रेस के बारे में दो फ़ील्ड:

<ResponseField name="current_energy" type="number | null">
  नियम बनाए जाने के समय एड्रेस पर उपलब्ध एनर्जी। यदि इसे पढ़ा नहीं जा सका तो `null`; नियम हर हाल में बन जाता है।
</ResponseField>

<ResponseField name="will_refill_now" type="boolean">
  `true` यदि `current_energy` पहले से थ्रेशोल्ड से नीचे है, यानी अगली जाँच — आमतौर पर एक मिनट के भीतर — खरीदेगी। `false` यदि एड्रेस पर पर्याप्त है, या स्तर पढ़ा नहीं जा सका।
</ResponseField>

    "target_address": "TYourRecipientAddress1234567890abc",

### त्रुटियाँ

| स्थिति | कोड | कब |
|--------|------|------|
| `400` | `INVALID_ADDRESS` | `target_address` मान्य TRON एड्रेस नहीं है |
| `400` | `CONTRACT_ADDRESS_NOT_SUPPORTED` | `target_address` एक स्मार्ट कॉन्ट्रैक्ट है |
| `403` | `FORBIDDEN` | API कुंजी के पास `buy_energy` स्कोप नहीं है |
| `409` | `AUTOREFILL_ADDRESS_TAKEN` | आपके खाते में इस एड्रेस के लिए पहले से एक एनर्जी नियम है — उसी को बदलें |
| `409` | `AUTOREFILL_LIMIT_REACHED` | आपके खाते में पहले से 20 एनर्जी नियम हैं; सीमा `error.limit` में भी दी जाती है |
| `422` | — | कोई फ़ील्ड गायब है या सीमा से बाहर है, या `duration` `"1h"` नहीं है |
| `429` | `RATE_LIMIT_EXCEEDED` | एक मिनट में नियम बनाने के 10 से अधिक अनुरोध |

```json
{
  "detail": {
    "error": {
      "code": "AUTOREFILL_LIMIT_REACHED",
      "message": "You already hold the maximum of 20 auto-refill rules. Delete one to add another.",
      "limit": 20
    }
  }
}
```

```json
{
  "detail": {
    "error": {
      "code": "AUTOREFILL_ADDRESS_TAKEN",
      "message": "Auto-refill for this address already exists"
    }
  }
}
```

सत्यापन त्रुटि फ्रेमवर्क के प्रारूप में आती है, जिसमें `detail` एक ऐरे होता है:

```json
{
  "detail": [
    {
      "type": "literal_error",
      "loc": ["body", "duration"],
      "msg": "Input should be '1h'",
      "input": "1d",
      "ctx": {"expected": "'1h'"}
    }
  ]
}
```

<Tip>
टाइमआउट के बाद नियम बनाने का अनुरोध दोबारा भेजना सुरक्षित है। यदि पहला अनुरोध सफल हो गया था, तो दोबारा भेजा गया अनुरोध दूसरा नियम बनाने के बजाय `409 AUTOREFILL_ADDRESS_TAKEN` लौटाता है; उसका `id` पाने के लिए [अपने नियमों की सूची देखें](/api-reference/auto-refill/list-energy-rules)।
</Tip>
