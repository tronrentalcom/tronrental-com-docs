कनेक्शन को वे अनुमतियाँ मिलती हैं जो आप सहमति स्क्रीन पर चुनते हैं। API कुंजी को वे स्कोप मिलते हैं जो आप डैशबोर्ड में उसे बनाते समय तय करते हैं। MCP सर्वर सिर्फ़ वही टूल्स सूचीबद्ध करता है जिन्हें ये अनुमतियाँ खोलती हैं (`tools/list`), और हर कॉल सर्वर पर फिर से जाँची जाती है।

| अनुमति | क्या खोलती है | कनेक्ट किया गया ऐप (OAuth) | API कुंजी |
|---|---|---|---|
| `view` | बैलेंस, इतिहास, रिपोर्ट, ऑर्डर, कोट, पता जाँच, ब्रॉडकास्टर कोटा और इवेंट, स्टेकिंग पोज़िशन, Node API प्लान और उपयोग | ✓ | ✓ |
| `deposit_view` | डिपॉज़िट पता, डिपॉज़िट, दूसरे कॉइन में डिपॉज़िट | ✓ | ✓ |
| `buy_energy` | एनर्जी ख़रीदना, पता सक्रिय करना, एनर्जी ऑटो-रिफ़िल, इनवॉइस | ✓ | ✓ |
| `buy_bandwidth` | बैंडविड्थ ख़रीदना और वापस लेना, बैंडविड्थ ऑटो-रिफ़िल, ऑटो बैंडविड्थ | ✓ | ✓ |
| `smart_mode` | Smart Mode | ✓ | ✓ |
| `transfer_packages` | ट्रांसफ़र पैकेज | ✓ | ✓ |
| `energy_resale` | Energy Resale | ✓ | ✓ |
| `broadcaster` | ब्रॉडकास्ट URL बनाना, बदलना और हटाना | ✓ | ✓ |
| `staking` | स्टेक, अनस्टेक, रिवॉर्ड क्लेम, रिवॉर्ड ऑटो-क्लेम | ✓ सिर्फ़ खाते का मालिक | ✓ सिर्फ़ खाते का मालिक |
| `node_api_plan` | Node API प्लान ख़रीदना, ट्रायल शुरू करना, ऑटो-रिन्यूअल | ✓ सिर्फ़ खाते का मालिक | ✓ सिर्फ़ खाते का मालिक |
| `recurring` | अपने-आप चलने वाला खर्च चालू करना — नीचे देखें | ✓ डिफ़ॉल्ट रूप से बंद | ज़रूरी नहीं |
| `withdraw` | निकासी | **कभी नहीं** | ✓ 2FA और IP व्हाइटलिस्ट के साथ |

## अपने-आप चलने वाला खर्च (`recurring`)

कुछ टूल्स कॉल के समय खर्च नहीं करते, बल्कि ऐसा खर्च चालू करते हैं जो बाद में चलता रहता है: ऑटो-रिफ़िल, ऑटो बैंडविड्थ, Smart Mode, Energy Resale, ब्रॉडकास्ट URL, Node API ऑटो-रिन्यूअल। कनेक्ट किए गए ऐप के लिए इन्हें बनाने या बदलने के लिए प्रोडक्ट की अनुमति के ऊपर `recurring` भी चाहिए। बंद करने और हटाने के लिए इसकी कभी ज़रूरत नहीं। Smart Mode को रोकने के लिए ज़रूरत है, क्योंकि वही टूल उसे फिर से चालू भी करता है।

<Warning>
  अपने-आप चलने वाला खर्च **दैनिक सीमा से बाहर** है और **ऐप डिस्कनेक्ट करने के बाद भी चलता रहता है**। इसे डैशबोर्ड में उसके पेज पर बंद करें।
</Warning>

## पहले टॉप-अप से पहले

जब तक खाते के टॉप-अप कुल 100 TRX नहीं हो जाते, सहमति स्क्रीन सिर्फ़ `view` और `deposit_view` देती है, और दिखाती है कि कितना टॉप-अप बाकी है। टॉप-अप के बाद ऐप को दोबारा कनेक्ट करें और और अनुमतियाँ चुनें — वही कनेक्शन अपडेट होता है।

## टीम खाते

सहमति स्क्रीन पर आप चुनते हैं कि ऐप किस खाते पर काम करेगा: आपका अपना या कोई टीम खाता जहाँ आप API कुंजियाँ प्रबंधित करते हैं। टीम सदस्य सिर्फ़ वही अनुमतियाँ दे सकता है जो उसकी भूमिका के पास हैं, `staking` या `node_api_plan` नहीं दे सकता, और दैनिक सीमा नहीं हटा सकता (`OAUTH_UNCAPPED_OWNER_ONLY`)।

## API कुंजी या कनेक्ट किया गया ऐप

| | कनेक्ट किया गया ऐप (OAuth) | API कुंजी |
|---|---|---|
| किसके लिए उपयुक्त | एजेंट या आपका ऐप इस्तेमाल करने वाले लोग | आपके अपने सर्वर और स्क्रिप्ट |
| दैनिक खर्च सीमा | डिफ़ॉल्ट रूप से 100 TRX | कोई नहीं |
| ख़रीद पर `max_price_trx` | ज़रूरी | वैकल्पिक |
| निकासी | कभी नहीं | `withdraw`, 2FA और IP व्हाइटलिस्ट के साथ |
| ऑर्डर `source` | `agent` | `api` |

API कुंजियाँ तब जारी होती हैं जब खाते के टॉप-अप कुल 100 TRX हो जाते हैं — देखें [ऑथेंटिकेशन](/hi/authentication)।
