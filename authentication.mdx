## API Key Authentication

All API requests require an API key passed in the `X-API-Key` header.

```bash
curl https://api.tronrental.com/v1/account/balance \
  -H "X-API-Key: your_api_key"
```

### Getting an API key

1. Sign up at [tronrental.com](https://tronrental.com/auth/register)
2. Go to [Dashboard → API Keys](https://tronrental.com/dashboard/api)
3. Click **Create API Key**
4. Copy and securely store your key — it's shown only once

A new email account is created only after you confirm the address: TronRental mails a 6-digit code, and the account exists once that code is entered.

### Signing up via the API (AI agents)

An agent or script can open an account and issue its first key without the website. It needs the user's **real** email: the account is created only with the code from that inbox.

**1. Start the sign-up** — no account is created yet, a 6-digit code is mailed to the address:

```bash
curl -X POST https://api.tronrental.com/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "<your-password>", "language": "en"}'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | The user's email — they must be able to read the code from it |
| `password` | string | Yes | At least 8 characters with an uppercase letter, a lowercase letter and a digit |
| `language` | string | No | Language of the email, default `en` |

```json
{
  "requires_email_code": true,
  "access_token": null,
  "refresh_token": null
}
```

The code is valid for 10 minutes. If a valid code is already pending, no second email is sent. To get a new code, call `POST /v1/auth/email-code/send` with `{"email": "...", "language": "en"}`: the previous code stops working, and an address gets at most 3 emails per hour.

**2. Confirm the email** — send the code together with the **same password** (it is not stored before this step). This creates the account and signs in:

```bash
curl -X POST https://api.tronrental.com/v1/auth/email-code/verify \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "code": "123456", "password": "<your-password>"}'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Same email as in step 1 |
| `code` | string | Yes | 6-digit code from the email |
| `password` | string | Yes for sign-up | Same password as in step 1 |
| `referral_code` | string | No | Referral code of the user who invited you |

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "session_id": "3f9c...",
  "token_type": "bearer",
  "is_new": true
}
```

**3. Create an API key** with the access token:

```bash
curl -X POST https://api.tronrental.com/v1/auth/api-keys \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name": "my-agent"}'
```

The `key` field of the response is the API key — it is shown only once.

| Status | Code | Meaning |
|--------|------|---------|
| `400` | `WEAK_PASSWORD` | The password does not meet the rules (the code is not spent) |
| `401` | `INVALID_CREDENTIALS` | Wrong or expired code |
| `403` | `EMAIL_DOMAIN_BLOCKED` | This email provider is not accepted |
| `409` | `EMAIL_EXISTS` | The email already has an account — sign in instead |
| `429` | `RATE_LIMIT_EXCEEDED` | Too many requests or emails, or 5 wrong codes in a row — request a new code |

<Note>
  The [MCP server](/resources/mcp-server) runs these steps with the `register` and `verify_email_code` tools.
</Note>

### IP Whitelist (optional)

You can restrict your API key to specific IP addresses for additional security. Configure this in the dashboard when creating or editing a key.

### Key permissions

Each API key carries **scopes** — the operations it is allowed to perform. You choose them in the
dashboard when you create or edit a key. A new key gets every read and write scope (buying energy and
bandwidth, Smart Mode, reading the balance and history, and more) except `withdraw`: that scope is
enabled separately and requires 2FA and an IP whitelist; enabling it, changing such a key's IP whitelist and regenerating the key are confirmed with your 2FA code or passkey. A request outside the key's scopes is refused
with HTTP `403`. The full list: [List API Key Scopes](/api-reference/account/api-key-scopes).

<Warning>
  Keep your API key secret. Do not expose it in client-side code, public repositories, or URLs.
</Warning>

## Node API keys

[Node API](/node-api/overview) — access to TRON full nodes at `node.tronrental.com` — has keys of its
own. You create them as endpoints in [Dashboard → Node API](https://tronrental.com/dashboard/node-api).
A Node API key works only at the node: this API answers it with `403 NODE_API_KEY_ONLY`. The API keys
described on this page do not work at the node either. See
[Node API → Endpoints and keys](/node-api/authentication).

## Key usage & request log

Every request authenticated with an API key is recorded for 7 days: method, path, status code, latency and client IP. Query strings are not stored in this view. Open [Dashboard → API Keys](https://tronrental.com/dashboard/api) and expand a key to see its recent requests; the **Last Used** column shows the most recent call (the auth-time mark is updated at most once per 5 minutes, the request log is exact). The log is available from the dashboard only — an API key cannot read its own log.

## Rate Limits

API keys are rate-limited per account, not per key: every key of one account shares a single budget. See [Rate Limits](/resources/rate-limits) for details.

## Errors

Authentication errors return HTTP `401`:

```json
{
  "detail": "Invalid or missing API key"
}
```

If your key is disabled or blocked, you'll receive HTTP `403`.
