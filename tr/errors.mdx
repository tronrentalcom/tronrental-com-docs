## Hata formatı

Hatalar üç biçimden birinde gelir. Uç noktaların çoğu ilkini kullanır; diğer ikisi belirli yollarda
bulunur ve istemcinizin aradığı bir hata kodunu kaçırmaması için burada listelenmiştir.

**Standart.** Programatik işleme için `detail.error` içine yerleştirilmiş bir `code`:

```json
{
  "detail": {
    "error": {
      "code": "INSUFFICIENT_BALANCE",
      "message": "Insufficient balance. Required: 12.5 TRX, available: 3.1 TRX"
    }
  }
}
```

**Hesap düzeyinde hız sınırı.** Aynı alanlar, ancak en üst düzeyde ve `detail` olmadan — bu yanıt,
istek uç noktaya ulaşmadan önce üretilir:

```json
{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests. Please try again later."}}
```

**Düz.** Para çekme doğrulama adımları `code` alanını `detail` ile yan yana koyar ve mesajın kendisi
`detail` içinde bulunur:

```json
{"detail":"Passkey verification required","code":"PASSKEY_REQUIRED"}
```

Bazı yanıtlarda hiç kod bulunmaz — istek doğrulaması (`422`) ve birkaç dahili kontrol, düz bir mesajla
`{"detail": "..."}` döndürür.

<Tip>
Kodu, bunlardan mevcut olan ilkinden okuyun: `detail.error.code`, sonra `error.code`, sonra `code`.
Hiçbiri yoksa HTTP durum koduna bakın ve `detail` alanının bir dize olduğunu asla varsaymayın —
standart biçimde o bir nesnedir.
</Tip>

## HTTP Durum Kodları

| Kod | Anlam |
|------|---------|
| `200` | Başarılı |
| `400` | Hatalı istek — geçersiz parametreler |
| `401` | Yetkisiz — eksik veya geçersiz API anahtarı |
| `402` | Ödeme gerekli — hesap bakiyesi yetersiz |
| `403` | Yasaklı — anahtar devre dışı, IP izin listesinde değil veya doğrulama gerekli |
| `404` | Bulunamadı |
| `409` | Çatışma — tekrarlanan istek veya kaynak çatışması |
| `422` | Doğrulama hatası — istek gövdesini kontrol edin |
| `429` | Hız sınırı aşıldı — bkz. [Hız Sınırları](/resources/rate-limits) |
| `500` | Sunucu hatası |
| `503` | Geçici olarak kullanılamıyor — kısa süre sonra tekrar deneyin |

## Yaygın hata kodları

Standart biçimde, `detail.error.code` altında döndürülür:

| Kod | Durum | Açıklama |
|------|--------|-------------|
| `INVALID_TOKEN` | `401` | API anahtarı eksik, bilinmiyor veya devre dışı |
| `ACCOUNT_BLOCKED` | `403` | Bu hesap için API erişimi engellendi |
| `FORBIDDEN` | `403` | İsteğin IP'si anahtarın izin listesinde değil |
| `INSUFFICIENT_BALANCE` | `402` | Bu işlem için hesap bakiyesi yetersiz |
| `INVALID_ADDRESS` | `400` | Geçerli bir TRON adresi değil |
| `CONTRACT_ADDRESS_NOT_SUPPORTED` | `400` | Hedef bir akıllı sözleşme — TRON ona kaynak devretmeyi yasaklar |
| `INVALID_VOLUME` | `400` | İstenen miktar izin verilen aralığın dışında |
| `INVALID_DURATION` | `400` | Süre, kabul edilen değerlerden biri değil |
| `ORDER_NOT_FOUND` | `404` | Sipariş kimliği mevcut değil |
| `RATE_LIMIT_EXCEEDED` | `429` | Çok fazla istek — bkz. [Hız Sınırları](/resources/rate-limits) |

## Para çekme doğrulama kodları

`POST /api/v1/account/withdrawal` bunları düz biçimde, `code` ile `detail` yan yana olacak şekilde
döndürür:

| Kod | Durum | Açıklama |
|------|--------|-------------|
| `WITHDRAW_SCOPE_REQUIRED` | `403` | API anahtarında `withdraw` kapsamı yok |
| `2FA_REQUIRED` | `403` | 2FA etkinleştirilmeli veya bir kod verilmeli |
| `IP_WHITELIST_REQUIRED` | `403` | Para çekmek için anahtarın IP izin listesi gerekir |
| `PASSKEY_REQUIRED` | `403` | Hesapta bir passkey var — para çekme bunu gerektirir |
| `INVALID_PASSKEY` | `403` | Passkey doğrulaması geçersiz, süresi dolmuş veya size ait değil |
| `INVALID_2FA_CODE` | `403` | 2FA veya yedek kod reddedildi |
| `RATE_UNAVAILABLE` | `503` | Döviz kuru geçici olarak kullanılamıyor — kısa süre sonra deneyin |

## Yeniden deneme stratejisi

`5xx` yanıtlarını üstel geri çekilmeyle yeniden deneyin. `429` için, yanıtta varsa `Retry-After`
başlığını tercih edin ve önce gövdeyi okuyun — her `429` bir hız sınırı değildir
(bkz. [Hız Sınırları](/resources/rate-limits)).

```python
import time
import requests

def api_call_with_retry(url, **kwargs):
    for attempt in range(3):
        resp = requests.get(url, **kwargs)
        if resp.status_code == 429:
            time.sleep(int(resp.headers.get("Retry-After", 2 ** attempt)))
            continue
        if resp.status_code >= 500:
            time.sleep(2 ** attempt)
            continue
        return resp
    raise Exception("Max retries exceeded")
```
