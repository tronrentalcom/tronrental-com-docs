## Аутентификация по API-ключу

Все API-запросы требуют передачи API-ключа в заголовке `X-API-Key`.

```bash
curl https://api.tronrental.com/v1/account/balance \
  -H "X-API-Key: your_api_key"
```

### Получение API-ключа

1. Зарегистрируйтесь на [tronrental.com](https://tronrental.com/auth/register)
2. Пополните баланс в [Личный кабинет → Пополнение](https://tronrental.com/dashboard/deposit): API-ключ выдаётся, когда пополнения в сумме достигают **100 TRX**
3. Перейдите в [Личный кабинет → API-ключи](https://tronrental.com/dashboard/api)
4. Нажмите **Создать API-ключ**
5. Скопируйте и надёжно сохраните ключ — он показывается только один раз

Новый аккаунт по email создаётся только после подтверждения адреса: TronRental присылает на почту 6-значный код, и аккаунт появляется, как только этот код введён.

### Пополнение до первого ключа

100 TRX — это сумма всех пополнений, когда-либо зачисленных на аккаунт; пополнение в USDT считается по сумме в TRX, которая была зачислена. Считается история, а не баланс: потраченный баланс ключ не отнимает. Пока сумма не достигла 100 TRX, `POST /v1/auth/api-keys` отвечает `403`:

```json
{
  "detail": {
    "error": {
      "code": "API_KEY_DEPOSIT_REQUIRED",
      "message": "API keys are available after a top-up of 100 TRX in total: top up 60 TRX more.",
      "required_trx": "100",
      "missing_trx": "60"
    }
  }
}
```

`required_trx` — порог, `missing_trx` — сколько ещё пополнить; оба в TRX, строками. [Лимиты API-ключей](/ru/api-reference/account/api-key-limits) заранее показывают те же два числа в `deposit_required_trx` и `deposit_missing_trx`. Та же проверка действует при включении ключа, который был выключен, потому что аккаунт ни разу не пополнялся. Ключей Node API порог не касается: их выдаёт тариф Node API.

### Регистрация через API (AI-агенты)

Агент или скрипт может открыть аккаунт, пополнить его и, когда пополнения достигнут 100 TRX, выпустить ключ без сайта. Для этого нужен **настоящий** email пользователя: аккаунт создаётся только с кодом из этого почтового ящика.

**1. Начните регистрацию** — аккаунт пока не создаётся, на адрес приходит 6-значный код:

```bash
curl -X POST https://api.tronrental.com/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "<your-password>", "language": "en"}'
```

| Поле | Тип | Обязательно | Описание |
|-------|------|----------|-------------|
| `email` | string | Да | Email пользователя — у него должен быть доступ к этой почте, чтобы прочитать код |
| `password` | string | Да | Не менее 8 символов, среди них заглавная буква, строчная буква и цифра |
| `language` | string | Нет | Язык письма, по умолчанию `en` |

```json
{
  "requires_email_code": true,
  "access_token": null,
  "refresh_token": null
}
```

Код действует 10 минут. Если действующий код уже ждёт ввода, второе письмо не отправляется. Чтобы получить новый код, вызовите `POST /v1/auth/email-code/send` с `{"email": "...", "language": "en"}`: прежний код перестаёт действовать, а на один адрес уходит не больше 3 писем в час.

**2. Подтвердите email** — отправьте код вместе с **тем же паролем** (до этого шага он нигде не сохраняется). Этот вызов создаёт аккаунт и выполняет вход:

```bash
curl -X POST https://api.tronrental.com/v1/auth/email-code/verify \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "code": "123456", "password": "<your-password>"}'
```

| Поле | Тип | Обязательно | Описание |
|-------|------|----------|-------------|
| `email` | string | Да | Тот же email, что и на шаге 1 |
| `code` | string | Да | 6-значный код из письма |
| `password` | string | Да, при регистрации | Тот же пароль, что и на шаге 1 |
| `referral_code` | string | Нет | Реферальный код пользователя, который вас пригласил |

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "session_id": "3f9c...",
  "token_type": "bearer",
  "is_new": true
}
```

**3. Пополните баланс** — для адреса пополнения достаточно access-токена. Отправьте TRX или USDT на `deposit_address` из ответа:

```bash
curl https://api.tronrental.com/v1/account/deposit \
  -H "Authorization: Bearer <access_token>"
```

С тем же заголовком работают баланс (`GET /v1/account/balance`), покупки и заказы, так что первый заказ ключа не ждёт. Access-токен действует 1 час; новый — входом через `POST /v1/auth/login` с `{"email": "...", "password": "..."}`.

**4. Создайте API-ключ**, когда пополнения аккаунта в сумме достигнут 100 TRX:

```bash
curl -X POST https://api.tronrental.com/v1/auth/api-keys \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name": "my-agent"}'
```

Поле `key` в ответе — это API-ключ; он показывается только один раз. Пока пополнений меньше 100 TRX, ответ — `403 API_KEY_DEPOSIT_REQUIRED`, а недостающая сумма — в `missing_trx` (см. «Пополнение до первого ключа» выше).

| Статус | Код | Значение |
|--------|------|---------|
| `400` | `WEAK_PASSWORD` | Пароль не соответствует требованиям (код при этом не расходуется) |
| `401` | `INVALID_CREDENTIALS` | Неверный или истёкший код |
| `403` | `EMAIL_DOMAIN_BLOCKED` | Этот почтовый сервис не принимается |
| `403` | `API_KEY_DEPOSIT_REQUIRED` | Пополнения аккаунта в сумме меньше 100 TRX — пополните ещё на `missing_trx` и создайте ключ |
| `409` | `EMAIL_EXISTS` | На этот email уже есть аккаунт — войдите в него |
| `429` | `RATE_LIMIT_EXCEEDED` | Слишком много запросов или писем либо 5 неверных кодов подряд — запросите новый код |

<Note>
  [Локальный MCP-пакет](/ru/agents/connect) проходит эти шаги инструментами `register`, `verify_email_code`, `get_deposit_address` и `create_api_key`.
</Note>

### Белый список IP (опционально)

Вы можете ограничить API-ключ определёнными IP-адресами для дополнительной безопасности. Настройте это в личном кабинете при создании или редактировании ключа.

### Разрешения ключа

Каждый API-ключ несёт **разрешения** (scopes) — операции, которые ему доступны. Их выбирают в
личном кабинете при создании или редактировании ключа. Новый ключ получает все разрешения на чтение и
запись (покупка энергии и bandwidth, Smart Mode, просмотр баланса и истории и другие), кроме `withdraw`:
его включают отдельно, и для этого нужны 2FA и белый список IP; включение, смена белого списка IP у такого ключа и его перевыпуск подтверждаются кодом 2FA или passkey. Запрос вне разрешений ключа получает
HTTP `403`. Полный список: [Список разрешений API-ключа](/ru/api-reference/account/api-key-scopes).

<Warning>
  Храните API-ключ в секрете. Не размещайте его в клиентском коде, публичных репозиториях или URL-адресах.
</Warning>

## Ключи Node API

[Node API](/ru/node-api/overview) — доступ к полным нодам TRON на `node.tronrental.com` — использует
собственные ключи. Их создают как эндпоинты в разделе
[Личный кабинет → Node API](https://tronrental.com/dashboard/node-api). Ключ Node API работает только
на ноде: этот API отвечает на него `403 NODE_API_KEY_ONLY`. API-ключи, описанные на этой странице, на
ноде тоже не работают. См. [Node API → Эндпоинты и ключи](/ru/node-api/authentication).

## Использование ключа и журнал запросов

Каждый запрос, аутентифицированный API-ключом, сохраняется на 7 дней: метод, путь, код ответа, задержка и IP клиента. Параметры запроса (query string) в этом журнале не показываются. Откройте [Dashboard → API Keys](https://tronrental.com/dashboard/api) и разверните ключ, чтобы увидеть его последние запросы; колонка **Last Used** показывает самый свежий вызов (отметка при аутентификации обновляется не чаще раза в 5 минут, журнал точен). Журнал доступен только из кабинета — API-ключ не может прочитать собственный журнал.

## Лимиты запросов

Лимиты запросов считаются по аккаунту, а не по ключу: все ключи одного аккаунта делят общий бюджет. Подробности см. в разделе [Лимиты запросов](/ru/resources/rate-limits).

## Ошибки

Ошибки аутентификации возвращают HTTP `401`:

```json
{
  "detail": "Invalid or missing API key"
}
```

Если ваш ключ отключён или заблокирован, вы получите HTTP `403`.
