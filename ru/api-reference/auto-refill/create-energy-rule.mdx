## Создать правило для энергии

Создаёт правило автопополнения для одного адреса. Начиная со следующей проверки, всякий раз, когда доступной энергии на адресе меньше `threshold_energy`, мы покупаем `add_volume` энергии на один час и списываем стоимость с вашего баланса. Как устроены проверки, стоимость и статусы, — в [обзоре](/ru/api-reference/auto-refill/overview).

Запрос только создаёт правило — сам он ничего не покупает. Нужен скоуп `buy_energy`. Чтобы сначала узнать цену одного пополнения, см. [Рассчитать цену пополнения энергии](/ru/api-reference/auto-refill/quote-energy-refill).

### Тело запроса

<ParamField body="target_address" type="string" required>
  Адрес TRON, который нужно держать обеспеченным (формат T..., 34 символа). Адреса контрактов отклоняются.
</ParamField>

<ParamField body="threshold_energy" type="number" required>
  Покупать, когда доступной энергии на адресе меньше этого значения. От 1 до 50 000 000.
</ParamField>

<ParamField body="add_volume" type="number" required>
  Сколько энергии покупать за одно пополнение. От 1 до 5 000 000. Держите значение не ниже `threshold_energy` — см. [предупреждение в обзоре](/ru/api-reference/auto-refill/overview#как-выбрать-значения).
</ParamField>

<ParamField body="duration" type="string" default="1h">
  Срок аренды для каждого пополнения. Принимается только `"1h"`; любое другое значение вернёт `422`.
</ParamField>

<ParamField body="label" type="string">
  Ваше собственное название правила, до 100 символов. Необязательно.
</ParamField>

### Ответ

Новое правило — с теми же полями, что в [Списке правил для энергии](/ru/api-reference/auto-refill/list-energy-rules), — плюс два поля о текущем состоянии адреса:

<ResponseField name="current_energy" type="number | null">
  Энергия, доступная на адресе в момент создания правила. `null`, если её не удалось прочитать; правило создаётся в любом случае.
</ResponseField>

<ResponseField name="will_refill_now" type="boolean">
  `true`, если `current_energy` уже ниже порога, и значит следующая проверка — обычно в течение минуты — сделает покупку. `false`, если на адресе достаточно энергии или уровень не удалось прочитать.
</ResponseField>

### Ошибки

| Статус | Код | Когда |
|--------|------|------|
| `400` | `INVALID_ADDRESS` | `target_address` — некорректный адрес TRON |
| `400` | `CONTRACT_ADDRESS_NOT_SUPPORTED` | `target_address` — смарт-контракт |
| `403` | `FORBIDDEN` | У API-ключа нет скоупа `buy_energy` |
| `409` | `AUTOREFILL_ADDRESS_TAKEN` | В вашем аккаунте уже есть правило для энергии на этот адрес — вместо этого измените его |
| `409` | `AUTOREFILL_LIMIT_REACHED` | В вашем аккаунте уже 20 правил для энергии; лимит также передаётся в `error.limit` |
| `422` | — | Поле отсутствует или вне диапазона, либо `duration` — не `"1h"` |
| `429` | `RATE_LIMIT_EXCEEDED` | Больше 10 запросов на создание за минуту |
| `503` | `AUTOREFILL_DISABLED` | Автопополнение энергии временно выключено; правило не создано — повторите позже |

```json
{
  "detail": {
    "error": {
      "code": "AUTOREFILL_LIMIT_REACHED",
      "message": "You already hold the maximum of auto-refill rules: 20 for energy and 20 for bandwidth, counted separately. Delete one to add another.",
      "limit": 20
    }
  }
}
```

```json
    "error": {

      "message": "Auto-refill for this address already exists"

  }

```

```json
{
  "detail": {
    "error": {
      "code": "AUTOREFILL_DISABLED",
      "message": "Auto-refill is temporarily unavailable; please try again later"
    }
  }

```

Ошибка валидации приходит в формате фреймворка, где `detail` — массив:

```json
{
  "detail": [
    {
      "type": "literal_error",
      "loc": ["body", "duration"],
      "msg": "Input should be '1h'",
      "input": "1d",
      "ctx": {"expected": "'1h'"}
    }
  ]
}
```

<Tip>
Повторять создание после таймаута безопасно. Если первый запрос прошёл, повтор вернёт `409 AUTOREFILL_ADDRESS_TAKEN`, а не создаст второе правило; чтобы узнать его `id`, [запросите список правил](/ru/api-reference/auto-refill/list-energy-rules).
</Tip>
