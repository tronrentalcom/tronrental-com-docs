## Журнал вебхуков

Последние попытки доставки, новые сверху — что мы отправили и что ответил ваш сервер.

### Параметры запроса

<ParamField query="page" type="integer">
  Номер страницы, от `1`. По умолчанию `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Записей на страницу, `1`–`100`. По умолчанию `50`.
</ParamField>

### Ответ

Массив записей.

<ResponseField name="id" type="number">
  ID записи журнала.
</ResponseField>

<ResponseField name="event_type" type="string">
  Какое событие доставлялось, например `order.updated`.
</ResponseField>

<ResponseField name="payload" type="object">
  Ровно тот конверт, который был отправлен — `event` / `data` / `timestamp`, те самые байты, по которым считалась подпись.
</ResponseField>

<ResponseField name="response_status" type="number">
  HTTP-статус, которым ответил ваш сервер. **`0` означает, что HTTP-ответа не было вовсе** — соединение, TLS-рукопожатие или чтение не удались либо истекли по таймауту.
</ResponseField>

<ResponseField name="attempts" type="number">
  Сколько из трёх попыток было сделано. `1` — получилось с первого раза.
</ResponseField>

<ResponseField name="created_at" type="string">
  Когда доставка завершилась, ISO-8601.
</ResponseField>

### Пример

```bash
curl https://api.tronrental.com/v1/webhooks/logs \
  -H "X-API-Key: your_api_key"
```

<Note>
  Две особенности, о которых стоит знать, прежде чем отлаживаться по этому журналу:

  - В нём перечислены доставки, отнесённые к вашим **API-ключам**, поэтому доставки `subscription.transfer` сегодня сюда не попадают, даже если были отправлены.
  - URL, который не удалось зарезолвить, или адрес из приватного диапазона **не дают строки вовсе** — пустой журнал не отличает «событий не было» от «адрес отвергнут». Если трафик ожидался, а его нет, проверьте URL в [Dashboard → API](https://tronrental.com/dashboard/api).
</Note>
