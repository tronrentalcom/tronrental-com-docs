## Limites de Taxa

Dois limites se aplicam a cada requisição: um **limite no nível da conta**, que cobre toda a API, e,
em alguns endpoints, um **limite próprio mais restrito**. Você atingirá aquele que for menor.

### Limite no nível da conta

Contado por **conta**, em uma janela fixa de um minuto. Todas as chaves de API de uma mesma conta
compartilham um único orçamento — criar mais chaves não aumenta o seu limite.

| Quem você é | Limite padrão |
|---|---|
| Conta com uma compra concluída, ou saldo de 10 TRX ou mais | 1000 requisições/minuto |
| Qualquer outra conta autenticada | 300 requisições/minuto |
| Requisições sem autenticação | 60 requisições/minuto por endereço IP |
| Consulta de `GET /api/v1/invoices/{invoice_id}` sem autenticação | 180 requisições/minuto por endereço IP |

Os orçamentos sem autenticação são contados separadamente para cada grupo de endpoints — preços,
status de fatura, consultas de endereço, autenticação e todo o restante —, de modo que consultar
preços nunca consome o orçamento das demais chamadas.

Estes são os valores padrão. Se a sua integração precisa de um teto maior, nós o elevamos para a sua
conta: fale conosco no [Telegram](https://t.me/TronRentalcom_bot).

<Note>
A janela é fixa, não deslizante: o contador zera no início de cada minuto. Um cliente que gasta todo
o seu orçamento no fim de um minuto e novamente no início do seguinte passará brevemente do dobro do
limite sem ser bloqueado. Trate isso como um artefato da janela, não como uma permissão — o mesmo
padrão de tráfego deslocado em alguns segundos é rejeitado.
</Note>

### Endpoints com um limite próprio mais restrito

| Endpoint | Limite | Contado por |
|---|---|---|
| `POST /api/v1/invoices` | 10 requisições/minuto | endereço IP |
| `POST /api/v1/account/withdrawal` | 1 requisição/minuto | conta |

Observe que `POST /api/v1/invoices` é contado por **endereço IP**, não por conta: se vários dos seus
clientes enviam requisições a partir do mesmo IP de saída, eles compartilham um único orçamento de 10
por minuto.

Todos os demais endpoints documentados não possuem limite próprio mais restrito — apenas o limite no
nível da conta acima se aplica a eles.

### Como é uma resposta 429

O corpo depende de qual limite você atingiu. Existem três formatos, portanto faça a análise de forma
defensiva, em vez de presumir um deles.

**Limite no nível da conta.** A resposta traz um cabeçalho `Retry-After` com o número de segundos de
espera:

```
HTTP/1.1 429 Too Many Requests
Retry-After: 37
```

```json
{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests. Please try again later."}}
```

**Limite do endpoint**, por exemplo em `POST /api/v1/invoices`. Não há cabeçalho `Retry-After`; a
janela é de um minuto:

```json
{"detail":{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests. Please try again later."}}}
```

**`POST /api/v1/account/withdrawal`.** Um `detail` em texto simples com os segundos restantes, sem
código de erro:

```json
{"detail":"Rate limit: try again in 42s"}
```

### Um 429 que repetir não resolve

`POST /api/v1/invoices` também responde `429` quando você já tem faturas não pagas demais — no máximo
**3 por endereço IP** e no máximo **5 por conta**. O limite por IP vale também para requisições
autenticadas, por isso normalmente é nele que você esbarra primeiro:

```json
{"detail":"Too many pending invoices (max 3)"}
```

Isto é um teto de faturas em aberto, não um limite de taxa, e esperar não o libera por si só. Pague
uma das faturas pendentes, ou deixe-a expirar, antes de criar outra.

### Novas tentativas

- Se a resposta trouxer o cabeçalho `Retry-After`, aguarde exatamente esse número de segundos.
- Caso contrário, use recuo exponencial, começando em um segundo.
- Nunca repita imediatamente.
- Leia o corpo antes de repetir: `Too many pending invoices` exige outra ação, não uma espera maior.

```python
import time
import requests

def post_with_retry(url, **kwargs):
    for attempt in range(3):
        resp = requests.post(url, **kwargs)
        if resp.status_code == 429:
            body = resp.text
            if "pending invoices" in body:
                raise RuntimeError(body)  # esperar nao vai ajudar
            delay = int(resp.headers.get("Retry-After", 2 ** attempt))
            time.sleep(delay)
            continue
        return resp
    raise RuntimeError("Max retries exceeded")
```
