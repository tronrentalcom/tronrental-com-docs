## Registro de webhooks

Tentativas de entrega recentes, as mais novas primeiro — o que enviamos e o que o seu servidor respondeu.

### Parâmetros de consulta

<ParamField query="page" type="integer">
  Número da página, a partir de `1`. Padrão `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Entradas por página, `1`–`100`. Padrão `50`.
</ParamField>

### Resposta

Um array de entradas.

<ResponseField name="id" type="number">
  ID da entrada de registro.
</ResponseField>

<ResponseField name="event_type" type="string">
  O evento que foi entregue, por exemplo `order.updated`.
</ResponseField>

<ResponseField name="payload" type="object">
  Exatamente o envelope que foi enviado, `event` / `data` / `timestamp` — os mesmos bytes sobre os quais a assinatura foi calculada.
</ResponseField>

<ResponseField name="response_status" type="number">
  Código HTTP com que o seu servidor respondeu. **`0` significa que nenhuma resposta HTTP chegou** — a conexão, o handshake TLS ou a leitura falharam ou expiraram.
</ResponseField>

<ResponseField name="attempts" type="number">
  Quantas das três tentativas foram feitas. `1` significa que deu certo na primeira.
</ResponseField>

<ResponseField name="created_at" type="string">
  Quando a entrega terminou, ISO-8601.
</ResponseField>

### Exemplo

```bash
curl https://api.tronrental.com/v1/webhooks/logs \
  -H "X-API-Key: your_api_key"
```

<Note>
  Duas lacunas que vale conhecer antes de depurar com este registro:

  - Ele lista entregas atribuídas às suas **chaves de API**, então hoje as entregas de `subscription.transfer` não aparecem aqui, mesmo tendo sido enviadas.
  - Uma URL que não conseguimos resolver, ou que resolve para um endereço privado, **não gera linha alguma** — um registro vazio não distingue «não houve eventos» de «o endereço foi recusado». Se você esperava tráfego e não vê nada, confira a URL em [Dashboard → API](https://tronrental.com/dashboard/api).
</Note>
