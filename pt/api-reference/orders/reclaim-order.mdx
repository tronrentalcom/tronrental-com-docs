## Recuperar pedido

Remove na hora a delegação da largura de banda do seu pedido — por exemplo, quando o endereço já fez a transferência para a qual o recurso foi alugado — sem esperar o fim do prazo. **O tempo não usado não é reembolsado.** Somente pedidos de largura de banda podem ser recuperados antes do prazo.

### Parâmetros de caminho

<ParamField path="order_id" type="number" required>
  ID do pedido — o `id` retornado por Buy Bandwidth.
</ParamField>

### Resposta

Retorna o objeto do pedido, igual ao Get Order. `status` mostra o que aconteceu:

| Status | Significado |
|--------|-------------|
| `reclaimed` | A largura de banda foi removida nesta mesma requisição; `undelegate_txid` é a transação na blockchain |
| `filled` | O pedido entrou na fila do próximo ciclo de recuperação, normalmente em até 30 segundos. O resultado chega no webhook `order.updated`, ou consulte Get Order |
| `reclaiming` | Uma recuperação deste pedido já está em andamento |
| `reclaim_failed` | A remoção não foi concluída do nosso lado após as tentativas. Nada a fazer da sua parte |

Uma chamada repetida para um pedido que já está em `reclaiming`, `reclaimed` ou `reclaim_failed` retorna o pedido sem alterações, então repetir é seguro. A chave de API precisa da permissão `buy_bandwidth`.

### Erros

| Código | Status | Quando |
|------|--------|------|
| `ORDER_NOT_FOUND` | `404` | Não existe esse pedido na sua conta |
| `ORDER_NOT_RECLAIMABLE` | `409` | O pedido ainda não foi entregue (`filled`) ou falhou |
| `BAD_REQUEST` | `400` | Não é um pedido de largura de banda |
| `FORBIDDEN` | `403` | A chave de API não tem a permissão `buy_bandwidth` |

### Exemplo

```bash
curl -X POST https://api.tronrental.com/v1/orders/12345/reclaim \
  -H "X-API-Key: your_api_key"
```
