## Criar Saque

<div>
  `POST /api/v1/account/withdrawal`
</div>

Saca TRX para qualquer endereço TRON. Taxa: 1 TRX.

### Corpo da requisição

<ParamField body="to_address" type="string" required>
  Endereço TRON de destino
</ParamField>

<ParamField body="amount_trx" type="string" required>
  Valor a sacar em TRX
</ParamField>

<ParamField body="currency" type="string">
  `TRX` (padrão) ou `USDT`. Com `USDT`, `amount_trx` contém o valor em USDT a enviar.
</ParamField>

<ParamField body="totp_code" type="string">
  Código 2FA (se o 2FA estiver ativado)
</ParamField>

### Cabeçalhos

<ParamField header="Idempotency-Key" type="string">
  Opcional, até 64 caracteres. Envie uma chave nova (um UUID, por exemplo) a cada novo saque e a mesma chave ao repetir uma requisição cuja resposta você não recebeu — a repetição devolve o primeiro saque em vez de criar um segundo.
</ParamField>

### Repetição segura

- A mesma chave com os mesmos `to_address`, `amount_trx` e `currency` retorna `200` com o saque criado pela primeira requisição, no estado atual. Nada é cobrado duas vezes.
- A mesma chave com outro corpo é recusada com `422` e o código `IDEMPOTENCY_KEY_REUSED`; uma chave com mais de 64 caracteres — com `422` e `IDEMPOTENCY_KEY_TOO_LONG`. As chaves valem dentro da sua conta e não expiram — nunca reutilize uma chave em outro saque.
- Um saque não finalizado (`pending`, `scheduled` ou `processing`) por vez: outra requisição enquanto ele existir recebe `400` com `You already have a pending withdrawal`.
- Depois de um saque criado com `Idempotency-Key`, o próximo pode ser criado em 5 segundos; sem o cabeçalho a pausa continua de 60 segundos (`429`, veja [Limites de requisições](/resources/rate-limits)).

### Exemplo

```bash
curl -X POST https://api.tronrental.com/v1/account/withdrawal \
  -H "X-API-Key: your_api_key" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f9c2b1e-5d4a-4c1e-9b3f-2a6d8e0c4f11" \
  -d '{
    "to_address": "TDestinationAddress...",
    "amount_trx": "100"
  }'
```

```json Response
{
  "id": 56,
  "to_address": "TDestinationAddress...",
  "amount_trx": "100.00",
  "fee_trx": "1.00",
  "status": "completed",
  "tx_hash": "a1b2c3d4e5f6...",
  "created_at": "2026-03-05T12:00:00Z"
}
```

## Listar Saques

<div>
  `GET /api/v1/account/withdrawals`
</div>

Retorna seu histórico de saques.

```bash
curl https://api.tronrental.com/v1/account/withdrawals \
  -H "X-API-Key: your_api_key"
```

```json Response
[
  {
    "id": 56,
    "to_address": "TDestinationAddress...",
    "amount_trx": "100.00",
    "fee_trx": "1.00",
    "status": "completed",
    "tx_hash": "a1b2c3d4e5f6...",
    "created_at": "2026-03-05T12:00:00Z"
  }
]
```

### Status dos saques

| Status | Descrição |
|--------|-----------|
| `pending` | Na fila para processamento |
| `completed` | TRX enviado, tx_hash disponível |
| `failed` | Falhou, valor reembolsado |
| `scheduled` | Criado no painel web; aguarda uma janela de cancelamento de 20 segundos antes do envio |
| `processing` | Sendo enviado para a rede |
| `cancelled` | Cancelado pelo usuário dentro da janela de cancelamento; valor devolvido |

Saques criados via chave de API são enviados imediatamente e nunca passam por `scheduled`. Linhas criadas no painel web trazem `execute_after` — o momento do envio, salvo cancelamento antes dele.

### Bloqueio de segurança após a alteração do e-mail

Durante 24 horas após a alteração do e-mail da conta, a criação de saques é rejeitada com `403` e o código de erro `WITHDRAWAL_EMAIL_COOLDOWN`. A resposta traz `retry_after_seconds` — o tempo restante até que os saques sejam desbloqueados:

```json Response
{
  "detail": {
    "error": {
      "code": "WITHDRAWAL_EMAIL_COOLDOWN",
      "message": "Withdrawals are temporarily blocked after an email change",
      "retry_after_seconds": 79214
    }
  }
}
```

Esse bloqueio se aplica a todos os tipos de sessão, incluindo chaves de API com o escopo `withdraw`. Se você não alterou o e-mail da conta, entre em contato com o suporte imediatamente.
