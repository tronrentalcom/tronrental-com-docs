## Configurar webhook

Establece la URL de webhook de la cuenta. Hay una sola URL por cuenta y ambos eventos van a ella.

<Warning>
**Una clave API no puede llamar a este endpoint.** Cambiar la URL del webhook —o leer el secreto de firma— requiere una sesión abierta por usted mismo en el sitio web. Con una clave API la petición se rechaza:

```json Response
{
  "detail": {
    "error": {
      "code": "FORBIDDEN_SESSION_TYPE",
      "message": "This action is not available for this session type"
    }
  }
}
```

De lo contrario, una clave robada bastaría para dirigir sus eventos al servidor de otra persona. Configure la URL en [Dashboard → API](https://tronrental.com/dashboard/api); en esa misma página se muestra el secreto de firma.
</Warning>

### Cuerpo de la petición

<ParamField body="url" type="string" required>
  URL del webhook. En este endpoint **solo HTTPS**, y no debe apuntar a `localhost`, `127.0.0.1`, `0.0.0.0` ni `::1`. Además, la entrega se rechaza en el momento del envío hacia cualquier host que resuelva a una dirección privada, loopback o link-local.
</ParamField>

### Respuesta

<ResponseField name="webhook_url" type="string">
  La URL ahora configurada.
</ResponseField>

<ResponseField name="webhook_secret" type="string">
  El secreto de firma para `X-Webhook-Signature`. Se genera la primera vez que se establece una URL en la cuenta y no cambia después.
</ResponseField>

```json Response
{
  "webhook_url": "https://yourserver.com/webhook/tronrental",
  "webhook_secret": "3f2a9c...64 hex characters..."
}
```

### La puerta del panel

El panel usa un segundo par de endpoints sobre los mismos campos de la cuenta: `GET /api/v1/account/webhook` para leer la URL y el secreto, y `PATCH /api/v1/account/webhook` para establecerlos o borrarlos. Aceptan los mismos valores con dos diferencias: `PATCH` admite también una URL `http://`, y enviar `{"webhook_url": null}` borra el webhook.

Borrar la URL **conserva** el secreto, de modo que volver a activar el webhook más adelante no invalida el código de verificación que ya tenga desplegado.

Ambos endpoints requieren también una sesión del sitio web.
