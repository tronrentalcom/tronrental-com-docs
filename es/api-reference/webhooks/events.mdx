## Registro de webhooks

Intentos de entrega recientes, los más nuevos primero: qué enviamos y qué respondió su servidor.

### Parámetros de consulta

<ParamField query="page" type="integer">
  Número de página, desde `1`. Por defecto `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Entradas por página, `1`–`100`. Por defecto `50`.
</ParamField>

### Respuesta

Un array de entradas.

<ResponseField name="id" type="number">
  ID de la entrada del registro.
</ResponseField>

<ResponseField name="event_type" type="string">
  El evento que se entregó, p. ej. `order.updated`.
</ResponseField>

<ResponseField name="payload" type="object">
  El sobre exacto que se envió, `event` / `data` / `timestamp`: los mismos bytes sobre los que se calculó la firma.
</ResponseField>

<ResponseField name="response_status" type="number">
  Código HTTP con el que respondió su servidor. **`0` significa que no llegó ninguna respuesta HTTP**: la conexión, el handshake TLS o la lectura fallaron o expiraron.
</ResponseField>

<ResponseField name="attempts" type="number">
  Cuántos de los tres intentos se hicieron. `1` significa que funcionó a la primera.
</ResponseField>

<ResponseField name="created_at" type="string">
  Cuándo terminó la entrega, ISO-8601.
</ResponseField>

### Ejemplo

```bash
curl https://api.tronrental.com/v1/webhooks/logs \
  -H "X-API-Key: your_api_key"
```

<Note>
  Dos limitaciones que conviene conocer antes de depurar con este registro:

  - Lista las entregas atribuidas a sus **claves API**, por lo que hoy las entregas de `subscription.transfer` no aparecen aquí aunque se hayan enviado.
  - Una URL que no pudimos resolver, o que resuelve a una dirección privada, **no genera ninguna fila**: un registro vacío no distingue entre «no hubo eventos» y «la dirección fue rechazada». Si esperaba tráfico y no ve nada, revise la URL en [Dashboard → API](https://tronrental.com/dashboard/api).
</Note>
