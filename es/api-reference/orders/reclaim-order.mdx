## Recuperar orden

Retira de inmediato la delegación del ancho de banda de tu orden —por ejemplo, cuando la dirección ya hizo la transferencia para la que se alquiló— sin esperar al final del plazo. **El tiempo no usado no se reembolsa.** Solo las órdenes de ancho de banda se pueden recuperar antes de tiempo.

### Parámetros de ruta

<ParamField path="order_id" type="number" required>
  ID de la orden: el `id` que devuelve Buy Bandwidth.
</ParamField>

### Respuesta

Devuelve el objeto de la orden, igual que Get Order. `status` indica lo que pasó:

| Estado | Significado |
|--------|-------------|
| `reclaimed` | El ancho de banda se retiró en esta misma solicitud; `undelegate_txid` es la transacción en la cadena |
| `filled` | La orden quedó en cola para el siguiente ciclo de recuperación, normalmente en menos de 30 segundos. El resultado llega en el webhook `order.updated`, o consulta Get Order |
| `reclaiming` | Ya hay una recuperación de esta orden en curso |
| `reclaim_failed` | La retirada no se completó de nuestro lado tras los reintentos. No tiene que hacer nada |

Una llamada repetida para una orden que ya está en `reclaiming`, `reclaimed` o `reclaim_failed` devuelve la orden sin cambios, así que reintentar es seguro. La clave de API necesita el permiso `buy_bandwidth`.

### Errores

| Código | Estado | Cuándo |
|------|--------|------|
| `ORDER_NOT_FOUND` | `404` | No existe esa orden en tu cuenta |
| `ORDER_NOT_RECLAIMABLE` | `409` | La orden aún no se ha entregado (`filled`) o falló |
| `BAD_REQUEST` | `400` | No es una orden de ancho de banda |
| `FORBIDDEN` | `403` | La clave de API no tiene el permiso `buy_bandwidth` |

### Ejemplo

```bash
curl -X POST https://api.tronrental.com/v1/orders/12345/reclaim \
  -H "X-API-Key: your_api_key"
```
