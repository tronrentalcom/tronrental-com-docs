Los clientes listos para usar (Claude, ChatGPT, Claude Code, Codex, Cursor) hacen todo esto por sí mismos. Esta página es para quienes desarrollan sus propios clientes MCP y apps. El flujo sigue la [especificación de autorización de MCP](https://modelcontextprotocol.io/specification/latest/basic/authorization).

## Descubrimiento

1. Un `POST https://mcp.tronrental.com/mcp` sin autenticar responde `401` con
   ```
   WWW-Authenticate: Bearer resource_metadata="https://mcp.tronrental.com/.well-known/oauth-protected-resource/mcp"
   ```
2. Los metadatos del recurso protegido (RFC 9728) indican el recurso `https://mcp.tronrental.com/mcp` y el servidor de autorización `https://mcp.tronrental.com`.
3. Los metadatos del servidor de autorización (RFC 8414) están en `https://mcp.tronrental.com/.well-known/oauth-authorization-server`. Sus endpoints son `/oauth/register`, `/oauth/authorize`, `/oauth/token` y `/oauth/revoke` en el mismo host.

## Registro del cliente

- **Dynamic Client Registration** (RFC 7591) en `/oauth/register`. Los clientes son públicos: `token_endpoint_auth_method` siempre es `none`.
- Se aceptan **Client ID Metadata Documents** de las plataformas compatibles.
- Las **redirect URI** deben estar en la lista permitida: loopback (`http://127.0.0.1:<any port>`, `http://localhost:<any port>`) y los callbacks de las plataformas compatibles. Cualquier otra URI se rechaza con `invalid_redirect_uri`. ¿Estás creando una app web con su propio callback? [Contacta con soporte](https://t.me/TronRentalcom_Help_bot) para que lo añadamos.

## Autorización

- Flujo authorization code con **PKCE, solo `S256`**.
- El parámetro `resource` es obligatorio y debe ser `https://mcp.tronrental.com/mcp`; los tokens se emiten para esta audiencia.
- `scope` enumera los [permisos](/es/agents/reference/permissions) que pide la app, separados por espacios, por ejemplo `view deposit_view buy_energy`. El usuario puede conceder menos; el `scope` de la respuesta del token indica lo concedido. `withdraw` no existe para OAuth y se rechaza con `invalid_scope`.
- El usuario inicia sesión (o se registra) en tronrental.com, elige la cuenta, los permisos y el límite diario de gasto, y aprueba. Una app que TronRental no conoce se muestra como no verificada.

## Tokens

| Token | Duración | Notas |
|---|---|---|
| Access token | 1 hora | Envíalo como `Authorization: Bearer <token>` a `/mcp` y a la [API REST](/es/api-reference/energy/get-prices) |
| Refresh token | 30 días | Se rota en cada uso. Reutilizar un refresh token antiguo revoca toda la conexión |

Solo se admiten los grants `authorization_code` y `refresh_token`; `client_credentials` no. Para llamadas de servidor a servidor usa una [clave API](/es/agents/build/overview#elige-cómo-autenticarte).

Con un access token, una app conectada también puede llamar a la API REST, pero solo a las rutas que figuran en la [referencia de herramientas](/es/agents/reference/tools); cualquier otra ruta responde `403 AGENT_ROUTE_CLOSED`.

## Revocación

- La app puede revocar sus tokens en `/oauth/revoke`.
- El usuario puede desconectar la app en **Aplicaciones conectadas**, en la [página API](https://tronrental.com/dashboard/api) del panel: la conexión y todos sus tokens se revocan a la vez, y la siguiente llamada a `/mcp` recibe `401` con `error="invalid_token"`.
- Hay una conexión por cuenta y app: volver a conectar la misma app actualiza sus permisos y su límite en lugar de añadir una segunda.
