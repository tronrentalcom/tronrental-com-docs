## Create Energy Rule

Creates an Auto Refill rule for one address. From the next check on, whenever the address has less available energy than `threshold_energy`, we buy `add_volume` energy for one hour and charge your balance. See the [overview](/api-reference/auto-refill/overview) for how checks, cost and statuses work.

The request only creates the rule — it does not buy anything itself. Requires the `buy_energy` scope. To see the price of one refill first, use [Energy Refill Quote](/api-reference/auto-refill/quote-energy-refill).

### Request body

<ParamField body="target_address" type="string" required>
  TRON address to keep supplied (T... format, 34 characters). Contract addresses are rejected.
</ParamField>

<ParamField body="threshold_energy" type="number" required>
  Buy when the address has less available energy than this. From 1 to 50,000,000.
</ParamField>

<ParamField body="add_volume" type="number" required>
  Energy to buy per refill. From 32,000 to 5,000,000. Keep it at or above `threshold_energy` — see the [warning in the overview](/api-reference/auto-refill/overview#choosing-the-numbers).
</ParamField>

<ParamField body="duration" type="string" default="1h">
  Rental duration of each refill. Only `"1h"` is accepted; any other value returns `422`.
</ParamField>

<ParamField body="label" type="string">
  Your own name for the rule, up to 100 characters. Optional.
</ParamField>

### Response

The new rule — the same fields as in [List Energy Rules](/api-reference/auto-refill/list-energy-rules) — plus two fields about the address right now:

<ResponseField name="current_energy" type="number | null">
  Energy available on the address at the moment the rule was created. `null` if it could not be read; the rule is created either way.
</ResponseField>

<ResponseField name="will_refill_now" type="boolean">
  `true` if `current_energy` is already below the threshold, so the next check — usually within a minute — will buy. `false` if the address has enough, or if the level could not be read.
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.tronrental.com/v1/energy/auto-refill \
  -H "X-API-Key: your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "target_address": "TYourRecipientAddress1234567890abc",
    "threshold_energy": 65000,
    "add_volume": 131000,
    "duration": "1h",
    "label": "Hot wallet"
  }'
```

```python Python
import requests
```

### Errors

| Status | Code | When |
|--------|------|------|
| `400` | `INVALID_ADDRESS` | `target_address` is not a valid TRON address |
| `400` | `CONTRACT_ADDRESS_NOT_SUPPORTED` | `target_address` is a smart contract |
| `403` | `FORBIDDEN` | The API key lacks the `buy_energy` scope |
| `409` | `AUTOREFILL_ADDRESS_TAKEN` | Your account already has an energy rule for this address — edit it instead |
| `409` | `AUTOREFILL_LIMIT_REACHED` | Your account already has 20 energy rules; the limit is also in `error.limit` |
| `422` | — | A field is missing or out of range, or `duration` is not `"1h"` |
| `429` | `RATE_LIMIT_EXCEEDED` | More than 10 create requests in a minute |
| `503` | `AUTOREFILL_DISABLED` | Auto Refill for energy is temporarily switched off; no rule was created — try again later |

A validation error comes in the framework's format, with `detail` as an array:

```json
{
  "detail": [
    {
      "type": "literal_error",
      "loc": ["body", "duration"],
      "msg": "Input should be '1h'",
      "input": "1d",
      "ctx": {"expected": "'1h'"}
    }
  ]
}
```

<Tip>
Retrying a create after a timeout is safe. If the first request went through, the retry returns `409 AUTOREFILL_ADDRESS_TAKEN` instead of making a second rule; [list your rules](/api-reference/auto-refill/list-energy-rules) to get its `id`.
</Tip>
