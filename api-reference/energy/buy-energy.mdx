## Buy Energy

Delegates energy to the specified TRON address. The cost is deducted from your account balance.

### Request body

<ParamField body="target_address" type="string" required>
  Target TRON address (T... format, 34 characters)
</ParamField>

<ParamField body="volume" type="number" required>
  Amount of energy to delegate (min 1, max 5,000,000)
</ParamField>

<ParamField body="duration" type="string" required>
  Rental duration: `"1h"` (1 hour only)
</ParamField>

<ParamField body="max_price_trx" type="string">
  Optional. The most you agree to pay for this order, in TRX — rental and fixed fee together. If the
  order would cost more, it is refused with `409 PRICE_CHANGED` and **nothing is charged**. Pass the
  `total_trx` from [Quote Price](/api-reference/energy/quote). A decimal string such as
  `"2.15"` (a JSON number is accepted too), greater than 0. Without it the order is bought at the
  current price, as before.
</ParamField>

### Headers

<ParamField header="Idempotency-Key" type="string">
  Optional, up to 64 characters. A retry with the same key and the same body returns the original
  order instead of buying again. After a successful order, the same key with a different body —
  a different `max_price_trx` included — returns `422 IDEMPOTENCY_KEY_REUSED`. After a refusal that
  charged nothing, such as `409 PRICE_CHANGED` or `402 INSUFFICIENT_BALANCE`, the key is free again:
  retry with it and the new price.
</ParamField>

### Response

<ResponseField name="id" type="number">
  Unique order identifier
</ResponseField>

<ResponseField name="status" type="string">
  Order status: `pending`, `filled`, `failed`, `submitted_unknown` (orders under 32,000 — see the note below)
</ResponseField>

<ResponseField name="txid" type="string | null">
  On-chain transaction id once the delegation is broadcast (null while `pending`)
</ResponseField>

<ResponseField name="price_trx" type="string">
  Total cost charged from your balance, in TRX
</ResponseField>

<ResponseField name="reclaim_at" type="string | null">
  ISO 8601 timestamp when the bandwidth rental is reclaimed (energy is reclaimed automatically by the provider)
</ResponseField>

<ResponseField name="activation_cost_trx" type="string">
  Address activation cost in TRX (`"0"` if the recipient is already activated)
</ResponseField>

### Show the price, then buy at that price

1. Call `GET /v1/energy/quote` with your `X-API-Key` and show `total_trx` to your user.
2. Call `POST /v1/energy/buy` with `max_price_trx` set to that `total_trx`.

The quote is rounded to the SUN exactly as the order is charged, so while the price is unchanged
the order costs exactly `total_trx`. The energy price follows the market and can move between the
quote and the purchase: then the purchase is refused with `409 PRICE_CHANGED` before anything is
charged — get a new quote, show it, and retry, with the same `Idempotency-Key` if you use one.

<Warning>
  `max_price_trx` covers the energy order only. If `target_address` is not activated on-chain yet,
  the activation is charged on top (`activation_cost_trx`) and is not checked against
  `max_price_trx`.
</Warning>

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.tronrental.com/v1/energy/buy \
  -H "X-API-Key: your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "target_address": "TYourRecipientAddress1234567890abc",
    "volume": 65000,
    "duration": "1h"
  }'
```

```python Python
import requests

resp = requests.post(
    "https://api.tronrental.com/v1/energy/buy",
    headers={"X-API-Key": "your_api_key"},
    json={
        "target_address": "TYourRecipientAddress1234567890abc",
        "volume": 65000,
        "duration": "1h",
    },
)
print(resp.json())
```

```javascript JavaScript
const resp = await fetch("https://api.tronrental.com/v1/energy/buy", {
  method: "POST",
  headers: {
    "X-API-Key": "your_api_key",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    target_address: "TYourRecipientAddress1234567890abc",
    volume: 65000,
    duration: "1h",
  }),
});
console.log(await resp.json());
```
</CodeGroup>


<Tip>
  **65,000 energy** covers one USDT transfer to an address that already holds USDT.
  Use **131,000** for first-time USDT recipients (new storage slot creation).
</Tip>

<Note>
  **Orders under 32,000 energy** are delivered from our own pool. If it cannot serve this address right now, the request fails with `503 POOL_EXHAUSTED` and **nothing is charged** — retry later or order 32,000 or more. While a previous order under 32,000 for the same address is still active, a new one is refused the same way.

  Such an order may come back as `submitted_unknown`: the delegation is broadcast but not yet confirmed in a block. It settles to `filled`, or to `failed` with a full refund, within minutes — poll [Get Order](/api-reference/orders/get-order).
</Note>
