## Archive Wallet

Moves your account's **closed** packages on the address into the archive: the dashboard shows them under *Archive* instead of the main list. Closed are `completed`, `expired`, `cancelled` and `failed_refunded`; a package that is active, paused, awaiting payment or activation stays in the main list.

Nothing else changes: the packages, their history and charges stay as they are, and [List Packages](/api-reference/transfer-packages/list) still returns them, with `archived_at` set. A package you buy later on the address is in the main list. Bring the wallet back with [Restore Wallet](/api-reference/transfer-packages/restore).

### Request body

<ParamField body="address" type="string" required>
  TRON address whose closed packages to archive
</ParamField>

### Response

<ResponseField name="address" type="string">
  The address from the request.
</ResponseField>

<ResponseField name="archived" type="boolean">
  Always `true`.
</ResponseField>

<ResponseField name="packages" type="number">
  How many packages went into the archive now; `0` — nothing to archive (no closed package, or all already archived).
</ResponseField>

### Example

```bash
curl -X POST https://api.tronrental.com/v1/transfer-packages/archive \
  -H "X-API-Key: your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "address": "TYourAddress..."
  }'
```

```json Response
{
  "address": "TYourAddress...",
  "archived": true,
  "packages": 3
}
```

### Errors

Returned in the [standard shape](/errors), under `detail.error.code`. After any of them nothing has changed.

| Code | Status | When |
|------|--------|------|
| `PACKAGE_NOT_FOUND` | `404` | Your account has no package on the address |
