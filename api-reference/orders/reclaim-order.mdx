## Reclaim Order

Undelegates the bandwidth of your order right away — for example, once the address has made the transfer it was rented for — instead of waiting for the end of the term. **The unused time is not refunded.** Only bandwidth orders can be reclaimed early.

### Path parameters

<ParamField path="order_id" type="number" required>
  Order ID — the `id` returned by Buy Bandwidth.
</ParamField>

### Response

Returns the order object, the same as Get Order. `status` tells what happened:

| Status | Meaning |
|--------|-------------|
| `reclaimed` | The bandwidth was undelegated within this request; `undelegate_txid` is the on-chain transaction |
| `filled` | The order is queued for the next reclaim cycle, usually within 30 seconds. The result arrives in the `order.updated` webhook, or poll Get Order |
| `reclaiming` | A reclaim of this order is already running |
| `reclaim_failed` | The undelegation did not go through on our side after retries. Nothing for you to do |

A repeated call for an order that is already `reclaiming`, `reclaimed` or `reclaim_failed` returns the order unchanged, so retries are safe. The API key needs the `buy_bandwidth` scope.

### Errors

| Code | Status | When |
|------|--------|------|
| `ORDER_NOT_FOUND` | `404` | No such order on your account |
| `ORDER_NOT_RECLAIMABLE` | `409` | The order is not delivered (`filled`) yet, or it failed |
| `BAD_REQUEST` | `400` | Not a bandwidth order |
| `FORBIDDEN` | `403` | The API key lacks the `buy_bandwidth` scope |

### Example

```bash
curl -X POST https://api.tronrental.com/v1/orders/12345/reclaim \
  -H "X-API-Key: your_api_key"
```
