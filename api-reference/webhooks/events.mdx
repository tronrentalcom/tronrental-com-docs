## Webhook Logs

Recent delivery attempts, newest first — what we sent and what your server answered.

### Query parameters

<ParamField query="page" type="integer">
  Page number, from `1`. Default `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Entries per page, `1`–`100`. Default `50`.
</ParamField>

### Response

An array of entries.

<ResponseField name="id" type="number">
  Log entry ID.
</ResponseField>

<ResponseField name="event_type" type="string">
  The event that was delivered, e.g. `order.updated`.
</ResponseField>

<ResponseField name="payload" type="object">
  The exact envelope that was sent, `event` / `data` / `timestamp` — the same bytes the signature was computed over.
</ResponseField>

<ResponseField name="response_status" type="number">
  HTTP status your server answered with. **`0` means no HTTP response arrived at all** — the connection, the TLS handshake or the read timed out or failed.
</ResponseField>

<ResponseField name="attempts" type="number">
  How many of the three attempts were made. `1` means it succeeded first try.
</ResponseField>

<ResponseField name="created_at" type="string">
  When the delivery finished, ISO-8601.
</ResponseField>

### Example

```bash
curl https://api.tronrental.com/v1/webhooks/logs \
  -H "X-API-Key: your_api_key"
```

<Note>
  Two gaps worth knowing before you use this log to debug:

  - It lists deliveries attributed to your **API keys**, so today `subscription.transfer` deliveries do not appear here even when they were sent.
  - A URL we could not resolve, or one that resolves to a private address, writes **no row at all** — an empty log does not distinguish "no events happened" from "the address was refused". Check the URL in [Dashboard → API](https://tronrental.com/dashboard/api) if you expected traffic and see nothing.
</Note>
