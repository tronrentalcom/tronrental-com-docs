## Create Withdrawal

<div>
  `POST /api/v1/account/withdrawal`
</div>

Withdraws TRX to any TRON address. Fee: 1 TRX.

### Request body

<ParamField body="to_address" type="string" required>
  Destination TRON address
</ParamField>

<ParamField body="amount_trx" type="string" required>
  Amount to withdraw in TRX
</ParamField>

<ParamField body="currency" type="string">
  `TRX` (default) or `USDT`. With `USDT`, `amount_trx` holds the USDT amount to send.
</ParamField>

<ParamField body="totp_code" type="string">
  2FA code (if 2FA is enabled)
</ParamField>

### Headers

<ParamField header="Idempotency-Key" type="string">
  Optional, up to 64 characters. Send a new key (a UUID, for example) with every new withdrawal, and the same key when you repeat a request whose answer you did not get — the repeat returns the first withdrawal instead of creating a second one.
</ParamField>

### Retrying safely

- The same key with the same `to_address`, `amount_trx` and `currency` returns `200` with the withdrawal the first request created, as it stands now. Nothing is charged twice.
- The same key with a different body is refused with `422` and the code `IDEMPOTENCY_KEY_REUSED`; a key longer than 64 characters — with `422` and `IDEMPOTENCY_KEY_TOO_LONG`. Keys are scoped to your account and do not expire — never reuse one for another withdrawal.
- One unsettled withdrawal (`pending`, `scheduled` or `processing`) at a time: another request while one is unsettled gets `400` with `You already have a pending withdrawal`.
- After a withdrawal created with `Idempotency-Key`, the next one may be created in 5 seconds; without the header the pause stays 60 seconds (`429`, see [Rate limits](/resources/rate-limits)).

### Example

```bash
curl -X POST https://api.tronrental.com/v1/account/withdrawal \
  -H "X-API-Key: your_api_key" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f9c2b1e-5d4a-4c1e-9b3f-2a6d8e0c4f11" \
  -d '{
    "to_address": "TDestinationAddress...",
    "amount_trx": "100"
  }'
```

```json Response
{
  "id": 56,
  "to_address": "TDestinationAddress...",
  "amount_trx": "100.00",
  "fee_trx": "1.00",
  "status": "completed",
  "tx_hash": "a1b2c3d4e5f6...",
  "created_at": "2026-03-05T12:00:00Z"
}
```

## List Withdrawals

<div>
  `GET /api/v1/account/withdrawals`
</div>

Returns your withdrawal history.

```bash
curl https://api.tronrental.com/v1/account/withdrawals \
  -H "X-API-Key: your_api_key"
```

```json Response
[
  {
    "id": 56,
    "to_address": "TDestinationAddress...",
    "amount_trx": "100.00",
    "fee_trx": "1.00",
    "status": "completed",
    "tx_hash": "a1b2c3d4e5f6...",
    "created_at": "2026-03-05T12:00:00Z"
  }
]
```

### Withdrawal statuses

| Status | Description |
|--------|-------------|
| `pending` | Queued for processing |
| `completed` | TRX sent, tx_hash available |
| `failed` | Failed, amount refunded |
| `scheduled` | Created from the web dashboard; waits out a 20-second cancel window before it is sent |
| `processing` | Being sent to the network |
| `cancelled` | Cancelled by the user inside the cancel window; amount refunded |

Withdrawals created with an API key are sent immediately and never pass through `scheduled`. Rows created in the web dashboard carry `execute_after` — the moment the transfer is sent unless it is cancelled before then.

### Security hold after an email change

For 24 hours after the account email is changed, creating a withdrawal is rejected with `403` and the error code `WITHDRAWAL_EMAIL_COOLDOWN`. The response carries `retry_after_seconds` — how long is left until withdrawals unlock:

```json Response
{
  "detail": {
    "error": {
      "code": "WITHDRAWAL_EMAIL_COOLDOWN",
      "message": "Withdrawals are temporarily blocked after an email change",
      "retry_after_seconds": 79214
    }
  }
}
```

This hold applies to every session type, including API keys with the `withdraw` scope. If you did not change the account email, contact support immediately.
